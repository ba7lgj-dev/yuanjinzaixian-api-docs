# 远近电量 V2：历史行程、载人标注与实时剩余距离

本文记录 V2 实际落地的接口、周期算法、模型公式、数据边界和验收规则。所有计算只在本机进行，不上传云端。

## 1. 实时电压边界

- 实时外电电压只来自 `device/GetDetail.external_voltage`，时间只认 `last_com_time`。
- 不主动定位、不追踪，代码中不存在 `e_cmd_query_location` 调用；小组件点击也只做一次 `GetDetail`。
- 历史轨迹中的 `external_voltage` 只用于识别长时间静置锚点，不用于骑行过程中的 SOC。
- 定位器电量 `power` 与 `acc_state` / `acc_power` 不参与任何电量或距离计算。

## 2. 历史数据接口

模块统一为 `location`，请求体使用 JSON，但 `Content-Type` 仍为 `application/x-www-form-urlencoded`。

| 接口 | 用途 | 关键字段 |
| --- | --- | --- |
| `location/QueryTrackDate` | 查询有轨迹的日期与日里程 | `date_begin`、`date_end`、`simei` |
| `location/QueryLocation` | 分页读取轨迹点 | `time_begin`、`time_end`、`last_time`、`limit_size`（默认 2000） |
| `location/PPoint` | 读取停留点 | `simei` 数组、`stop_time=180`、`last_time`、`last_simei` |
| `location/PDistance` | 读取平台行程段 | `simei` 数组、`time_begin`、`time_end`、`last_start_time`、`last_simei` |

轨迹点解析字段：`time`、`lat`、`lon`、`wgs`、`altitude`、`speed`、`direction`、`distance`、`ptype`、`external_voltage`。

- 速度原始值除以 10 得到 km/h；整段都缺失时，用区间距离和时长推算平均速度。
- `distance` 视为与上一点之间的分段距离；非法或缺失时用 Haversine 计算。
- 海拔仅在 `altitudeUsable` 为真且数值在 -500–5000m 之间时参与地形特征。

同步策略：

- 首次登录或切换设备后，以 31 天为窗口回填最近 730 天，已完成的非近期日期会跳过。
- 日常增量同步最近 2 天；`HistorySyncWorker` 每 24 小时运行一次，网络受限，失败不影响实时采样。
- 同一天内按日期去重，轨迹点主键为 `simei + timeSec + latE6 + lonE6`。

## 3. 静置锚点

两层锚点：

- **显示锚点**：与实时稳定锁一致，同一静止周期、日里程不变、至少两个不同通讯时间且电压差不超过 0.05V。
- **训练锚点**：在显示锚点基础上，静置不少于 150 分钟、无充电迹象、数据新鲜。

历史锚点来自平台停留点：

- 只取持续 150 分钟以上的停留。
- 在停留结束前 30 分钟内，至少两个带外电电压的点，跨度不少于 10 分钟。
- 首尾电压差不超过 0.05V，取最后一点的电压，`grade = TRAINING`。

## 4. 行程周期与骑行区间

两个相邻有效锚点之间若检测到实际位移，就构成一个 `trip_cycles` 记录：

- 起点锚点电压 / SOC → 终点锚点电压 / SOC。
- 距离取“轨迹累计距离”和“平台 PDistance 累计距离”的较大值。
- 跨午夜周期归入开始日期；距离由日里程增量和轨迹距离共同核对。
- 平台 `PPoint` 停留点把周期切成多个骑行区间；不足 30 秒的空隙不会生成区间。
- 处理中会合并短于 30 秒的边界，避免碎段。

标注规则：

- 最近 7 天可编辑，超过 7 天只读，更早记录按月份折叠。
- 每个骑行区间标注 1–4 人（含骑行者，每人约 70kg），也可以取消标注。
- 支持在区间中点拆分、取消暂停边界以合并相邻区间、将暂停边界前后移动 5 分钟。
- 周期进入训练必须同时满足：
  1. 起点和终点都是 `TRAINING` 锚点；
  2. 区间内没有充电事件；
  3. 每个骑行区间都标注了人数；
  4. 区间距离覆盖周期总距离至少 95%；
  5. 起止 SOC 有下降；
  6. 周期距离在 0.1–200km 之间，时长不超过 48 小时。

## 5. 实时剩余距离

维护 `range_state`：

- `activeAnchorKey`：当前锚点。
- `distanceSinceAnchorKm`：锚点以来累计距离。
- `lastDayKey` / `lastDayDistanceKm`：用于计算平台日里程增量。
- `currentPeopleCount`：当前载人数量，默认 1。

距离累计：

- 同一本地日期使用 `day_distance` 正增量。
- 跨日时把新一天已发生的日里程计入累计。
- 单次增量异常（超过 50km）丢弃，避免平台跳变污染。

预测：

```
每人基准电耗 socPerKm = 2.5 / 0.85^(人数 - 1)   // %/km
锚点可行驶距离 anchorRange = 锚点 SOC / socPerKm
剩余距离 remaining = max(0, anchorRange - 锚点以来已行距离)
```

锚点失效条件：检测到充电、标记满电 / 空电、修改满空电压、切换设备或登出。失效后回退到普通电压续航估算，小组件右侧显示百分比而不是公里。

## 6. 本地模型

训练目标是 SOC 消耗率 `socDropPerKm = (起点 SOC - 终点 SOC) / 里程`，按车型和电池单独训练。

| 可用周期数 | 模型 |
| --- | --- |
| < 5 | 物理基准 |
| 5–9 | 按人数和 SOC 区间的中位数 |
| 10–29 | 带 L2 正则的本地线性回归 |
| ≥ 30 | 分 SOC 区间回归（0–40 / 40–60 / 60–80 / 80–100） |

特征向量：

1. 人数
2. 平均速度
3. 每公里累计爬升
4. 每公里累计下降
5. 下坡距离比例
6. 正加速度均值
7. 负加速度均值
8. 动能回收代理量 `(下降米数 × 平均速度 / 25 + 负加速度 × 20) / 公里`

回归使用 8 个特征加截距，`lambda = 6.0`，特征标准化后求解。动能回收系数允许为负，用来抵消部分电耗。

启用规则：

- 每次新增合格标注后自动重新训练。
- 用留一交叉验证 MAE 比较新旧模型；新模型误差不超过旧模型的 102% + 0.001 才启用。
- 被拒绝的模型仍保留在 `model_versions`，可以回滚或一键恢复物理基准。

## 7. 数据生命周期

- 轨迹点、历史锚点、周期、区间、平台停留和平台行程保留 730 天。
- 超过 730 天的原始数据删除，`monthly_summaries` 保留每月周期数、距离和平均 SOC 消耗。
- 模型版本与满空标定长期保留。
- 数据库版本 7，升级仅新增历史相关表，保留原有电压历史、账号、设备、昵称和标定。

## 8. 已知限制

- 平台没有电流、实时功率和 BMS 数据，模型学习的是“电压 SOC 变化与相对能耗”，不宣称得到真实瓦时。
- 历史同步只导入账号有权访问的数据；无权限或平台缺失的日期直接跳过。
- 载人数量是相对负载，不是精确重量；每人按 70kg 估算。
- WorkManager 周期受华为 / 荣耀省电策略影响，不保证严格按 15 分钟或 1 小时执行。
- 历史回填耗时较长，进度与失败原因在历史页展示，不阻塞实时电量。

## 9. 验收清单

- 代码中不存在主动定位调用；实时电压只用 `last_com_time`。
- 小组件严格 4×1，右侧优先显示实时公里，否则显示百分比；点击只刷新不打开 App。
- 首页大数字为剩余公里，下面是 SOC 电量条、锚点电压、已行距离和 1–4 人切换。
- 历史页最近 7 天可编辑，超过 7 天折叠只读；未完整标注的周期不会进入训练。
- 修改人数、标注、合并、拆分、移动暂停边界后模型自动重训。
- 低于 5 个周期显示物理基准，5–9 显示中位数，10 个以上显示回归。
- `testDebugUnitTest` 与 `assembleDebug` 通过。
